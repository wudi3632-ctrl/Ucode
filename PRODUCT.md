# Product

## Register

product

## Users

UCode serves developers, students, researchers, educators, and privacy-sensitive Windows users who need to work on a real codebase from a removable drive or an unfamiliar computer. They want a coding Agent that starts quickly, works locally by default, explains what it actually read, and never changes a project without review.

## Product Purpose

UCode is a Windows-first, USB-portable coding Agent workbench. Its primary job is to let a user open a project, ask grounded questions, propose and review code changes, run commands and tests, and inspect Git state without installing a full IDE. Success means four dependable daily workflows: grounded project answers, reviewed file changes, persistent terminal work, and isolated Agent edits.

## Brand Personality

Precise, calm, trustworthy. UCode should feel like a disciplined engineering instrument: compact enough for daily work, clear enough for a first-time user, and honest about model and tool limitations.

## Anti-references

- Generic AI dashboards with purple gradients, glowing glass cards, and decorative “thinking” theatrics.
- Chat interfaces that turn every message, tool result, and status into a large nested card.
- Full IDE chrome, dense toolbars, and panels that compete with the task.
- Raw transport logs, tool JSON, token events, or private reasoning presented as useful activity.
- Canned capability text or success language that is not backed by real files and operations.
- Fixed layouts that hide the composer or become unusable when the window is resized.

## Design Principles

1. **Evidence before confidence.** Every project claim, change, and completion state is grounded in a real file, Diff, command, or test result.
2. **Review before side effects.** Writes and execution are visible, bounded, and reversible by default.
3. **One task, one clear surface.** Reveal context progressively and keep the conversation as the primary workspace.
4. **Portable without feeling temporary.** The application must remain lightweight and movable while feeling as polished as an installed desktop product.
5. **Small-model honesty.** Deterministic routing and tools compensate for limited local inference; the UI never pretends process health equals answer quality.

## Accessibility & Inclusion

Target WCAG 2.1 AA contrast for text and interactive controls. All core actions must be keyboard reachable with visible focus. Panel resizing needs a keyboard alternative. Status cannot rely on color alone. Reduced-motion settings must disable spatial animation while preserving state feedback. Layout must remain usable at Windows display scaling and the configured minimum window size.
