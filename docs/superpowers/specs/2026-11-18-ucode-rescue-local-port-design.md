# UCode Rescue 本机端口冲突诊断设计

日期：2026-11-18  
状态：依据已批准的 Rescue 架构与“按推荐直接实施”授权进入实现  
目标：Windows 10/11 x64、U 盘便携、离线优先

## 1. 目标

让用户可以用自然语言询问“3082 端口是否被占用”“localhost:3000 为什么启动失败”“哪个进程监听 8080”，UCode 使用真实本机证据回答，而不是把本机端口误路由为需要联网许可的远端 TCP 探测，也不依靠模型猜测进程。

本阶段只做 R0 只读诊断。即使用户说“释放端口”或“修复端口冲突”，UCode 也不会结束进程、停止服务、改防火墙或运行任意 shell；它会识别占用者并给出有证据的下一步。

## 2. 方案选择

采用独立工具 `network.local_port.inspect@1`，而不是复用通用 PowerShell 或扩张 `network.tcp.probe`：

- 本机监听表是纯本地证据，不应请求 R1 网络授权；
- 固定 schema 可以限制端口、协议、输出和隐私；
- 本机“是否有监听者”和远端“能否完成 TCP 握手”是不同事实，不能混为一个工具；
- 后续若增加安全的服务级修复，可以继续绑定本工具的 evidence id，而无需开放任意进程控制。

拒绝在本阶段实现自动终止 PID。进程终止不可逆，可能破坏数据库、编辑器、代理、安全软件或系统服务，不符合 Rescue 的最小变更与可回滚原则。

## 3. 输入契约

工具只接受：

```json
{ "port": 3082, "protocol": "tcp" }
```

约束：

- `port` 必须是 1-65535 的十进制整数；
- 当前版本只接受 `tcp`；
- 请求中必须出现明确端口语境，例如“端口 3082”“port 3082”“localhost:3082”或 `127.0.0.1:3082`；
- URL 路径、版本号、PID、错误码和普通数字不能被误当成端口；
- 明确的非本地主机继续走现有 R1 `network.tcp.probe`，不能被降级为本机监听查询；
- 通配符、端口范围、列表、零、负数、溢出值和带 shell 字符的输入安全停止。

一次请求只查询一个端口。多端口扫描不在产品范围内。

## 4. 输出与隐私边界

输出最多包含：

```json
{
  "port": 3082,
  "protocol": "tcp",
  "occupied": true,
  "listeners": [
    {
      "localAddress": "127.0.0.1",
      "pid": 1234,
      "processName": "node",
      "ownerKind": "user_process"
    }
  ],
  "truncated": false
}
```

边界：

- 最多返回 16 个监听者，稳定排序并去重；
- `localAddress` 只显示监听地址，不显示远端连接；
- `processName` 只显示可执行文件基名，不显示完整路径；
- 不读取或返回命令行、环境变量、用户名、会话内容、窗口标题、文件句柄或网络 payload；
- `ownerKind` 只允许 `system`、`service_host`、`user_process`、`unknown`；
- 无权限读取进程名时保留 PID 并标记 `unknown`，不能把“未知”说成“未占用”；
- 工具超时 10 秒，stdout 上限 64 KiB。

## 5. 执行与路由

实现独立模块 `rescue_local_port.rs`，负责：

1. 从请求解析唯一、明确的本机 TCP 端口；
2. 用固定 PowerShell 探针读取 `Get-NetTCPConnection -State Listen -LocalPort <port>`；
3. 仅用固定环境变量传递数值端口，不拼接用户或模型文本；
4. 按 PID 查询进程基名并映射有界 `ownerKind`；
5. 返回结构化 `ProbeOutput`，由现有 evidence graph 计算摘要。

路由优先级：

1. 明确本机端口冲突或 localhost 监听问题 → R0 本机端口；
2. 明确非本地主机与端口 → 现有 R1 TCP 探测；
3. 只有泛化“端口异常”而无端口号 → 请求补充端口，不执行探针；
4. 本机端口请求不得再执行适配器、路由、代理或外网探测，避免无关证据。

## 6. 诊断语义

形成三个事实状态：

- `occupied`：至少一个真实 TCP listener；假设“端口被占用”受支持；
- `available`：探针成功且没有 listener；假设被反驳；
- `unavailable`：探针失败、超时或输出无效；保持未知，不能声称空闲。

当占用时，下一步说明占用者 PID/进程名，并建议用户确认该进程是否预期。用户要求“释放”时，仍不得自动终止进程；如果将来增加操作模块，必须按进程身份、服务归属、可回滚性和用户审批重新设计。

## 7. 桌面体验

沿用 Rescue 证据卡和任务收据，不新增独立 tab：

- 活动行显示“检查本机 TCP 端口 3082”；
- 结论显示“端口正在监听”或“未发现监听者”；
- 证据详情显示监听地址、PID、进程名和 owner kind；
- 空闲、失败、超时使用不同文案；
- 收据必须明确“只读诊断，没有结束进程或修改网络配置”。

不显示原始 PowerShell、完整进程路径或宽泛“已修复”提示。

## 8. 验收

自动化测试必须覆盖：

- 中文/英文/localhost/127.0.0.1 的显式端口解析；
- 远端主机不进入本机工具；
- 范围、列表、注入字符、无端口、溢出端口拒绝；
- occupied、available、unavailable 三种证据与假设；
- 进程名缺失不会误判为空闲；
- 输出上限、超时、最多 16 个监听者和隐私字段；
- 同一“服务启动失败”症状在测试 listener 存在与不存在时产生不同结论；
- 明确“释放端口”仍保持零 mutation；
- 工具注册表 id/version/risk 唯一且为 R0。

真实 Windows 验收使用测试进程临时监听随机 loopback 端口，先验证 occupied，再关闭测试 listener 验证 available。测试进程必须由测试自身创建和清理，不触碰用户已有进程。打包桌面至少完成一次真实对话并核对 evidence、任务收据和零副作用。

## 9. 非目标

- 不扫描端口范围；
- 不查询远端连接历史；
- 不抓包；
- 不改防火墙、端口代理、URL ACL 或保留端口；
- 不结束进程或停止服务；
- 不开放任意 `netstat`、PowerShell 或模型生成命令；
- 不声称端口空闲就证明应用一定能启动，绑定权限、地址族和应用配置仍可能失败。
