# UCode 输入历史与附件清晰度设计

日期：2026-11-17  
状态：待书面规格确认

## 目标

让高频输入更快，同时不破坏多行编辑、中文输入法和附件安全边界。用户可以用上下方向键找回当前对话中的历史输入，并能在添加附件前理解支持范围、添加后看清实际结果。

## 范围

本轮包含：

- 当前对话内的用户输入历史导航。
- 历史导航的轻量状态提示。
- 附件按钮、加载状态、限制说明和错误反馈的可理解性。
- 对现有附件选择、哈希校验和 Executor 绑定链路进行真实测试。
- 在 README 或应用帮助中准确说明文本文件支持边界。

本轮不包含：

- PDF、DOCX、XLSX、图片 OCR 或其他二进制内容解析。
- 跨会话的全局命令历史。
- 自动上传附件、网络同步或附件持久化。
- 扩大现有附件安全上限。

## 输入历史交互

历史仅来源于当前活动对话的真实用户消息，按时间从旧到新排列。连续重复消息去重，最多保留最近 50 条。

输入框行为：

- 输入为空时，按 `↑` 进入历史并显示最近一条输入。
- 输入非空且光标位于文本绝对起点时，按 `↑` 进入历史；进入历史模式后，继续按 `↑` 向旧记录移动。
- 只有已经处于历史模式时，`↓` 才向新记录移动；这样普通草稿中的 `↓` 始终保留原生光标行为。
- 越过最新历史记录时恢复进入历史前的原始草稿，包括空草稿。
- `Esc` 退出历史模式并恢复原始草稿。
- `Shift+Enter` 仍插入换行；普通 `Enter` 仍发送。
- `event.isComposing` 为真或键码为 229 时不拦截方向键，避免破坏中文输入法。
- 未进入历史模式时，多行文本中的 `↑/↓` 继续执行原生光标移动；自动换行也不会被误判为历史边界。
- 用户手动修改召回的内容后退出历史浏览状态，并把修改后的内容作为当前草稿。
- 切换历史不移除或替换当前已经添加的附件。

进入历史后，输入框右下方显示低强调状态，例如“历史 2/8”。状态使用现有主题变量和短距离淡入，不改变输入框高度。退出历史后状态消失。

## 组件边界

新增独立的纯逻辑模块管理历史状态，职责包括：

- 从当前对话时间线提取、排序和去重用户输入。
- 保存进入历史前的草稿。
- 计算上一个、下一个、退出历史后的文本与索引。
- 判断方向键是否位于允许接管的文本边界。

`Conversation` 只负责把当前历史、光标位置和键盘事件交给该模块，并应用返回结果。这样历史规则可以脱离 DOM 单元测试，避免继续扩大已经较复杂的对话组件。

## 附件体验与安全边界

“＋”按钮增加明确的 `title` 和辅助说明：“添加上下文文件（最多 8 个 UTF-8 文本）”。选择期间保留现有省略号加载反馈，并增加可访问的加载名称。

附件链路保持现有安全设计：

- 使用 Windows 原生多文件选择器。
- 每轮最多 8 个文件。
- 单文件不超过 256 KiB。
- 一轮送入模型的附件上下文不超过 120,000 bytes。
- 只接受非空、有效 UTF-8、无 NUL 字节的普通文件。
- 拒绝符号链接和 Windows 重解析点。
- 项目内文件保留相对路径；项目外文件只作为不暴露路径的只读快照。
- 发送前重新读取并校验 SHA-256；选择后发生变化则停止并要求重新添加。
- 选择记录 30 分钟过期，发送完成后立即清除。
- 附件令牌、摘要和内容必须一起通过 Executor 协议校验。

附件不根据扩展名武断放行或拒绝；只要内容满足 UTF-8 文本规则即可添加。界面要明确显示被接受、被截断和被拒绝的文件及原因。

## 文件格式说明

Agent 的重点文本索引覆盖：

`md, txt, js, mjs, cjs, ts, tsx, jsx, py, rs, go, java, kt, c, h, cpp, hpp, cs, json, jsonl, yaml, yml, toml, ini, cfg, xml, html, css, scss, sql, sh, ps1, bat, cmd, log, csv`

安全写入面向项目内 UTF-8 文本文件。Python、JavaScript 和 TypeScript 具有额外的跨语言与语法候选校验；其他文本格式仍经过路径、摘要、审批和事务写入校验。图片、PDF、Office 文档、压缩包、数据库和可执行文件不作为可编辑文本支持。

## 错误处理

- 附件选择器取消不显示错误，也不改变当前选择。
- 单个附件失败不丢弃同批次其他有效附件。
- 附件加载失败后恢复按钮可用状态并把焦点返回输入框。
- 历史为空时方向键保持原生行为，不显示状态。
- 活动对话或项目切换时重置历史浏览索引和附件选择，但从新对话重新计算历史。
- 发送失败恢复原输入和附件时，也退出历史浏览状态，避免索引与草稿不一致。

## 测试与验收

自动测试必须覆盖：

1. 空输入按 `↑` 召回最近消息，连续按键按顺序浏览。
2. `↓` 越过最新记录恢复原始草稿。
3. `Esc` 恢复草稿。
4. 多行文本中间的方向键不触发历史。
5. 文本边界、空历史、连续重复消息和 50 条上限。
6. 中文输入法组合事件不触发历史。
7. 历史切换不移除附件。
8. 附件的项目内、外部只读、过大、二进制、非 UTF-8、符号链接、总量上限、过期、内容变化和移除行为。
9. Executor 拒绝伪造令牌、摘要不匹配和外部附件路径。

真实桌面验收必须覆盖：

- 在已完成多轮对话中使用 `↑/↓/Esc`，观察草稿与“历史 n/m”状态。
- 编辑多行消息，确认方向键仍能正常移动光标。
- 添加一个项目内 UTF-8 文件和一个项目外 UTF-8 文件，发送问题并核对聊天中的附件标签与读取证据。
- 尝试添加二进制文件和超限文件，确认错误友好且其他有效附件仍可发送。
- 在浅色、深色主题下检查输入框、历史提示、附件 chip 和错误状态。

## 完成标准

功能只有在自动测试、生产构建和真实 Tauri 桌面流程全部通过后才算完成。不得仅以 demo bridge 或浏览器预览作为附件可用性的证据。
