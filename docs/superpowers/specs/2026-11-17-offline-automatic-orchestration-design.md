# UCode 离线自动编排设计

## 产品目标

UCode 是可放入 U 盘携带、优先在本机离线运行的桌面代码助手。核心体验不是暴露更多工程面板，而是让用户用一句自然语言完成尽可能多的工作，并且在真正修改项目之前仍能看见、理解和批准影响。

本轮调整遵循四条原则：

1. 默认离线。聊天、项目理解、文件读取、Diff、终端和本地 Git 安全流程均不依赖网络；远程模型和远程 Git 只能由用户显式开启。
2. 自动编排。简单任务直接执行，复杂任务自动使用最多三个只读分析 Agent；用户不需要配置 Agent 数量、角色或工作区。
3. 单一交付。并行 Agent 只负责收集架构、测试和风险证据，主 Agent 汇总后生成一个回答或一份可审查 Diff，避免多个 Agent 产生互相冲突的修改。
4. 风险时打断。读取和分析自动进行；文件写入、终端命令、应用修改或合并等有副作用的操作继续要求批准。

## 信息架构

右侧工作区只保留四个一级入口：

- 开始：显示当前任务状态、自动并行分析和结果证据。
- Diff：审查待批准或已应用的文件变更。
- 文件：浏览并读取当前项目。
- 终端：运行和检查本地命令。

Git 和 Agents 不再作为一级标签：

- Git 后端继续承担 Diff、Worktree 隔离、变更校验和本地版本安全；不自动初始化仓库，也不要求联网。
- Agents 后端继续保留只读与隔离编辑能力；正常界面只展示自动编排产生的紧凑活动记录，不展示手工任务表单。

## 路由与澄清

请求先经过确定性路由，再进入本地模型：

- 普通聊天：不读取项目，不调用工具。
- 代码示例：生成 Markdown 代码块，不写文件。
- 项目问答：读取必要文件后回答。
- 修改任务：分析、提出变更，批准后写入并验证。

独立数字、单个标点和缺少指代对象的极短片段不会直接交给小模型。UCode 应结合有限的上一轮类型给出具体澄清，例如询问数字是函数参数、行号还是任务选项，防止模型续写旧答案。

## 自动并行分析

只有满足明确复杂度信号的项目问题或修改任务才启动只读 Scout：

- 请求涉及整个项目、架构、跨模块、重构、安全或性能；
- 同时要求多个独立目标；
- 明确提及多个文件或模块；
- 项目规模和请求范围共同超过单次读取的合理边界。

Scout 使用固定且可解释的分工，按任务裁剪为二至三个：

1. 实现定位：入口、依赖和相关文件。
2. 验证分析：测试、失败模式和回归风险。
3. 配置边界：构建、运行环境和安全限制。

Scout 结果必须作为有长度限制的事实上下文交给主 Agent，而不是只在界面上制造“多 Agent”动画。简单聊天、明确单文件读取和简单编辑永不触发 Scout。

## 证据语义

证据卡只描述当前一轮，不得累计整个会话的历史来源。

- 以最近一次 `user.message` 为边界收集来源、命令、测试、变更和批准决策。
- 首轮使用 Ticket 原始请求；后续轮使用最近的用户消息。
- 普通聊天没有读取项目时，明确显示“本轮不需要项目证据”，并说明回答来自本地模型。
- SHA-256 只证明证据回执内容未被改写，不代表模型答案天然正确。

## 桌面主题

网页内容主题与 Windows 原生窗口主题必须同步：

- 深色映射为原生深色标题栏。
- 浅色映射为原生浅色标题栏。
- 跟随系统交给系统管理，并在系统主题变化时同步页面。

## 验收标准

1. 浅色主题下原生标题栏不再保持黑色。
2. 输入 `15` 等低信息内容时返回针对性澄清，不复读旧代码。
3. 新一轮普通聊天的证据卡不包含上一轮读取过的文件。
4. 右侧没有 Git 和 Agents 一级标签，非 Git 项目可正常使用。
5. 简单任务不启动 Scout；复杂项目分析自动启动二至三个 Scout，并将结果用于最终回答。
6. 所有本地 Git 操作保持离线；不新增后台网络请求。
7. Node、React、Rust 自动测试通过，并使用打包后的桌面应用完成真实多轮验证。
