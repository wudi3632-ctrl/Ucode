# UCode 可验证 AI 开发小队设计

## 1. 产品定义

UCode 不再以“复刻 Codex 桌面端”或“缩小版 DSH”为目标。它是一款可装入 U 盘携带、默认离线运行、面向中小型代码任务的可验证 Agent 工作台。

核心承诺：

> 把一支可验证的 AI 开发小队装进 U 盘。

用户只需要描述目标。简单任务保持普通对话体验；复杂任务由 UCode 自动拆分为可观察的执行流。本地小模型先完成能力范围内的工作，只有特定节点超出可靠边界时，才允许用户显式授权更强模型处理该节点。所有文件修改仍通过本地 Diff、审批、测试和回滚闭环。

## 2. 产品边界

### 2.1 稳定承诺

首个稳定版本只承诺：

1. 理解中小型项目的用途、结构和关键文件；
2. 定位并解释具有真实文件或错误证据的问题；
3. 完成一至五个文件的小型修改；
4. 生成或运行测试，展示真实结果；
5. 提供可审查、可拒绝、可回滚的修改批次。

### 2.2 实验能力

以下能力只能标记为实验性，不得宣传为稳定完成：

- 大范围架构重构；
- 数十文件联动修改；
- 多仓库协作；
- 数小时无人值守开发；
- 无法通过测试、类型检查或事实来源验证的开放式任务。

### 2.3 非目标

UCode 不建设完整 Git 客户端、通用浏览器自动化平台、云端项目管理系统或要求用户手工配置 Agent 拓扑的专家控制台。Git、Worktree、Ticket、Effect 和证据仍作为后台安全基础存在。

## 3. 核心交互

### 3.1 简单任务

问候、概念解释、指定文件读取和明确的小修改直接执行，不展示多 Agent 编排。用户看到普通对话、必要的文件活动和最终结果。

### 3.2 复杂任务

复杂任务在对话中展开紧凑执行流：

```text
登录失败修复                         本地执行

● 理解任务
├─ ✓ 定位登录入口        本地 Scout · 4 个来源
├─ ✓ 检查认证测试        本地 Scout · 2 个来源
├─ ✓ 分析失败原因        Qwen 1.5B
├─ ● 生成最小修改        Coder
├─ ○ 运行测试
└─ ○ 等待审查 Diff
```

执行流展示真实状态，不展示私有思维过程。节点默认只显示任务、状态、模型、耗时和证据数量；展开后显示实际来源、结构化结论、失败原因和后续动作。

### 3.3 能力升级

本地模型不足时，UCode 不自动上传项目，也不笼统提示“换更强模型”。它必须定位到具体节点并说明原因：

```text
架构判断超出本地模型的可靠范围。
是否仅将已脱敏的 3 个相关文件交给已配置的增强模型分析？
```

授权必须包含：目标模型、发送的文件、内容摘要、预计用途和当前节点。拒绝升级后，任务可降级为本地有限结论或请求用户缩小范围。

## 4. 编排架构

### 4.1 角色

| 角色 | 职责 | 默认实现 |
|---|---|---|
| Router | 判断聊天、读取、修改、澄清及复杂度 | 确定性规则优先 |
| Scout | 定位入口、测试、配置和依赖 | 本地小模型，只读 |
| Coder | 在已锁定范围内生成代码 | 本地代码模型 |
| Planner | 跨模块拆分与依赖排序 | 可选增强模型 |
| Reviewer | 审查 Diff、兼容性和风险 | 与 Coder 独立的模型或规则 |
| Verifier | 路径、摘要、测试、类型检查和来源校验 | 非模型程序 |
| Judge | 根据证据判定完成、失败或待确认 | 状态机与策略 |

### 4.2 编排原则

1. 单 Agent 足够时不得启动多个 Agent；
2. Agent 必须具有不同任务、上下文或验证责任；
3. 相同小模型不得通过自由讨论互相确认结论；
4. Scout 只返回结构化事实和来源；
5. Coder 只接收完成任务所需的最小上下文；
6. Reviewer 不获得直接写入权限；
7. Verifier 的事实结果高于模型自述；
8. 主 Agent 只交付一份最终回答或一个可审查修改批次。

### 4.3 执行图

任务被表示为有向无环图。每个节点至少包含：

- 节点 ID、角色和目标；
- 输入产物和依赖节点；
- 模型或确定性执行器；
- 文件与工具权限；
- 状态、开始时间和结束时间；
- 结构化输出和证据引用；
- 重试上限和失败策略；
- 是否需要用户批准。

首版只支持固定模板生成的浅层 DAG，不开放任意拖拽式编程。可视化是执行状态的投影，Rust Ticket/Assignment/Effect 状态仍是唯一事实源。

## 5. 模型策略

### 5.1 默认离线

默认组合继续使用本地 Router/Controller 与 Qwen2.5-Coder 1.5B。确定性操作不调用模型；本地模型只承担文本理解、局部分析和代码生成。

### 5.2 异构模型

模型注册表记录：

- 提供商与模型 ID；
- 本地或远程；
- 上下文长度；
- 代码、规划、视觉、审查等能力标签；
- 是否允许接收项目内容；
- 用户配置的成本和隐私等级；
- 最近真实任务成功率与延迟，而非宣传分数。

首版增强模型通过 OpenAI-compatible 端点接入。不同节点可以选择不同模型，但网络模型始终需要满足用户的内容边界设置。

### 5.3 小模型价值假设

小模型多 Agent 仅在以下条件下被认为有价值：

- 跨文件任务成功率比单 Agent 提升至少 15%；
- 虚假完成率不增加；
- 平均耗时不超过单 Agent的两倍；
- 简单任务完全不触发多 Agent；
- 失败能安全降级，且不会产生未经验证的修改。

若基准不满足这些条件，UCode 保留单 Agent Harness，停止宣传本地多 Agent 增益。

## 6. 界面设计

### 6.1 视觉语言

视觉方向为“安静的工程仪器”：

- 浅色使用温暖灰白，深色使用石墨黑；
- UCode 淡绿色只用于主行动、活动节点和成功状态；
- 消息正文弱化气泡，保持自然文档排版；
- 执行流使用细线、紧凑节点和克制动画；
- Diff、测试、证据和文件使用同一套卡片、圆角与间距；
- 技术细节默认折叠；
- 原生标题栏、托盘、通知、拖动和缩放保持桌面质感。

### 6.2 信息架构

左侧保留项目与会话；中间是对话、执行流和最终交付；右侧只在审查文件、Diff 或终端时出现。

普通用户不看到 Agent 数量、Worktree 路径、模型端口或手工编排表单。设置页提供本地默认、允许的增强模型、隐私边界和高级诊断。

### 6.3 证据展示

大型证据收据改为一行结果摘要：

```text
✓ 已完成 · 修改 2 个文件 · 3 项测试通过 · 可回滚
```

展开后才展示来源、命令、测试、Effect、批准记录和 SHA-256。证据严格限定当前轮次。

## 7. 同模型对照基准

### 7.1 对照组

主评测使用相同 Qwen2.5-Coder 1.5B 权重、相同硬件和相同上下文预算：

1. Bare：裸模型，仅提供请求；
2. ReAct：通用工具定义和通用循环，主要依赖模型规划；
3. UCode Single：UCode 路由、索引、策略和验证，禁用 Scout；
4. UCode Team：UCode 自动编排，最多两个只读 Scout。

云端 Codex 或其他强模型只作为体验上限参考，不参与 Harness 主评分。

### 7.2 任务集

任务必须来自至少十个不同的一次性项目，禁止重复同一 calculator 轨迹。每类至少十项：

- 指令遵循与澄清；
- 文件定位、解释和总结；
- 单文件修改与测试；
- 二至五文件的诊断和修改；
- 路径越界、虚构文件、失败测试和恢复。

每个任务包含可机械判定的预期产物、允许文件、测试命令和禁止行为。原始请求与评分规则在运行前固定。

### 7.3 指标

- 首次成功率；
- 最终完成率；
- 虚假完成率；
- 未核验文件或结论数量；
- 工具调用错误率；
- 首字时间、总耗时和模型调用次数；
- 峰值 CPU 与内存；
- 用户批准、澄清和人工纠正次数。

虚假完成采用最高惩罚。失败但诚实停止优于错误地声称完成。

### 7.4 结果发布

基准输出机器可读 JSON、任务级日志摘要和 Markdown 报告。报告同时展示成功、失败、跳过和限制，不选择性隐藏不利结果。任何“提升”必须同时提供分母、重复次数、硬件、模型摘要和置信范围。

## 8. 安全与恢复

- 读取自动执行但受项目根目录、索引和大小限制；
- 写入、终端副作用、合并和网络内容传输继续审批；
- Scout 永远只读；
- 编辑节点使用单一主 Agent和一个 Effect 批次；
- 节点最多重试一次，禁止无限循环；
- 应用关闭或崩溃后从 SQLite 任务图恢复；
- 模型输出不得扩大 Mandate；
- 未通过来源或测试验证的结论标记为“未核验”，不能进入完成证据。

## 9. 分阶段实施

### 阶段一：证明价值

实现四组同模型基准，运行真实任务并发布完整结果。在数据证明之前，不新增多 Agent 营销措辞。

### 阶段二：建立执行流体验

把现有事件活动投影为紧凑 DAG，合并重复思考与证据卡，完成桌面主题和响应式布局验证。

### 阶段三：混合模型节点

加入模型能力注册表和节点级显式授权，让增强模型只处理获得批准的有限上下文。

### 阶段四：高级模板

数据证明编排有效后，允许高级用户保存任务模板，但仍不开放无约束的自由编排。

## 10. 验收标准

1. 简单任务没有 Agent 图噪声；
2. 复杂任务自动出现真实执行流；
3. 每个节点能追溯模型、来源、状态和产物；
4. 本地模式断网可完成稳定承诺范围内的任务；
5. 网络模型不会在未授权时收到项目内容；
6. 同模型四组基准可在新的一次性工作区重复运行；
7. 报告能够明确回答 UCode Harness 和多 Agent是否产生净收益；
8. 未达到多 Agent收益门槛时，产品自动回退为单 Agent定位；
9. 所有写入仍保留 Diff、审批、测试和回滚；
10. README 不再声称 UCode 是 Codex 或 DSH 的完整替代品。
