# UCode 可验证 AI 开发小队实施计划

## Phase 1 — 同模型 Harness 基准

1. 在 `benchmarks/harness-comparison/` 建立公开、一次性、可机械评分的任务清单和夹具生成器。
2. 实现四个可切换 Runner：Bare、Generic ReAct、UCode Single、UCode Team；所有组共享同一 Coder 端点、温度、上下文预算和超时。
3. 先覆盖问答、项目读取、单文件修改、跨文件分析和安全失败五类代表任务；每个任务固定允许文件、预期事实、测试和禁止行为。
4. 记录成功、虚假完成、越界、模型调用次数、工具调用次数、首字时间和总耗时。
5. 输出逐任务 JSON、汇总 JSON 和 Markdown 报告；保留失败，不把云端模型混入主分数。
6. 为评分器、任务清单、隔离和报告生成添加 Node 自动测试。

## Phase 2 — 执行流投影

1. 将 Ticket、Assignment、Effect 和验证事件投影为稳定的浅层 DAG。
2. 用紧凑执行流替换重复活动卡与大型证据卡。
3. 简单任务不显示 Agent 图；复杂任务显示模型、来源、耗时、状态和产物。
4. 增加键盘、浅深主题、窗口缩放和减少动态效果测试。

## Phase 3 — 异构模型节点

1. 增加模型能力注册表和节点级 Provider 选择。
2. 本地节点默认自动执行；远程节点显示发送范围并等待明确授权。
3. Planner、Coder、Reviewer 与 Verifier 使用不同权限；Verifier 始终由本地程序掌控。
4. 增加失败降级、断点恢复和网络内容边界测试。

## Phase 4 — 数据驱动的产品决策

1. 若 UCode Team 相对 Single 的跨文件成功率提升不足 15%，禁用自动 Team 营销和默认触发。
2. 若收益成立，再增加高级任务模板；不开放无约束拖拽式编排。
3. 更新 README、能力边界和公开截图，只陈述实测结论。

## 当前实施切片

本轮先完成 Phase 1 的公开基准基础、自动测试和一轮真实本地模型试跑。Phase 2–4 只保留接口边界，不在基准结果出来前扩大实现范围。
